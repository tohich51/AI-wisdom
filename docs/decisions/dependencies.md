## Правило

Версии фиксируются точно. Совместимость с рантайм-сервисами из PRODUCT-SPEC
устанавливается spike-карточками, а не предполагается. Если библиотека
вынуждает заменить выбранную архитектуру — это blocker/proposal, а не тихая
подмена.

## Решение по блокеру C07: OIDC-библиотека

C07 не мог редактировать `pyproject.toml`/`requirements.lock` (один владелец),
поэтому использовал `httpx` + `PyJWT` для всего: discovery, построение authorize
URL, PKCE, code exchange и проверка ID-токена.

**Решение владельца lockfile: `authlib==1.8.0` добавлен и закреплён.**

Обоснование: `httpx` — транспорт, `PyJWT` — криптография подписи и claims.
Но choreography code flow (state, PKCE, обмен кода, разбор ID-токена)
писалась вручную, а карточка прямо запрещает «никакой собственной реализации
OAuth». Ручная разводка потока — именно то, что ревьюер справедливо замечает.
`authlib` даёт этот поток библиотекой.

Что это НЕ меняет: текущий httpx+PyJWT путь продолжает работать и остаётся
покрыт тестами. Следующая волга должна перевести token-exchange на
`authlib.client.OAuth2Client`, сохранив `TokenVerifier` для проверки
issuer/audience/JWKS. До тех пор C07 остаётся `implemented_unverified`
относительно Keycloak-ноги, и это не изменилось.

Побочно: `Authlib` тянет `cryptography>=45.0.1` и `joserfc>=1.6.1` — оба уже
были в дереве, новых транзитивных зависимостей не добавилось.

## Ограничения среды, влияющие на установку

1. **pip в этой песочнице**: дефолтный индекс не работает ни для одного
   пакета. Рабочая конфигурация —
   `--index-url https://pypi.org/simple/ --trusted-host pypi.org --trusted-host files.pythonhosted.org`.
   Это зашито в `justfile` (PIP_INDEX) и безвредно на обычном хосте.
2. **PEP 668**: системный Python защищён, поэтому `just prepare` создаёт `.venv`.
3. `requirements.lock` — авторитетный pin-набор (60 строк, сгенерирован из
   реально установленного набора). `uv.lock` в этом handoff не генерировался:
   uv 0.12.17 присутствует, но канонический lock выбранного формата
   фиксируется на C36 по результатам приёмки.

## Что осталось непроверенным

- `mcp` 2.3.0 импортируется, но **второй независимый MCP-клиент в этой среде
  отсутствует**. A01–A20 по MCP-ноге не исполнимы здесь → E03 pending.
- OpenViking не устанавливался и не запускался (C04).
- Keycloak требует JVM, которой нет → E03 pending.
