# Быстрая разработка AI-wisdom

Правила применяются к новым незакреплённым пакетам; sealed/release contracts сохраняются. Подготовка правил не регистрирует Cloud-клиентов и не запускает разработку функций. Проверки local-first; сеть — для согласованной подготовки, реальных интеграций и provider checks. Hosted CI не служит циклом каждой правки, но обязательный gate не отменяется. PAYG coding fallback запрещён; push/deploy — только в соответствующем scope. Пользовательские изменения сохраняются, секреты и приватные книги не отправляются, токены не попадают в логи.

1. Root + до трёх независимых пакетов в отдельных workspaces, disjoint resource locks, frozen interfaces. Для текущей волны обязателен порядок: внутренний MiniMax review → независимый Sol 6.1 medium на xorek → root integration. Один ограниченный артефакт проходит этот цикл; root фиксирует итог. Дополнительный reviewer только для прямо названного unresolved risk или строго требуемой policy. После fix перепроверяется изменённое поведение и связанные риски, не весь проект.

2. Для волны держать три готовых task packet и два buffer packet; ради WIP лишние задачи не создавать. Пока один пакет running/waiting/review/fix/blocked, root направляет, готовит или принимает другие. Общий wait — только после исчерпания полезной независимой работы в разрешённой области.

3. Task packet: objective, exact base SHA, allowed files, dependencies, frozen interfaces, checks, output. Точная матрица — ссылкой на [TEST-MATRIX.md](TEST-MATRIX.md), план волн — на [PARALLEL-WAVES.md](PARALLEL-WAVES.md); команды не угадываются. Root независимо применяет артефакт и выполняет acceptance checks; статус executor/model их не заменяет.

4. `MiniMax-M3.1-Flash-Preview` (thinking) использует существующую OAuth-подписку; выбор model/subscription/capabilities проверяется, а не предполагается. Text chat не имеет filesystem и tests и только готовит артефакт. Отсутствующий secret или capacity — blocker своей lane; независимые lanes продолжаются.

5. Переиспользуются текущие модули, официальные библиотеки, OSS. Speculative React rewrite, смена платформы, новый orchestrator и изменение product/model concurrency запрещены. Сохраняются одна существующая product generation и один OpenViking writer.

6. Capacity evidence относится к проверенному resource/lease. Неизвестная capacity → bounded probe, допустимые максимум три независимых calls при подходящем бюджете ресурсов; WIP снижается только у provider с `429`/resource failure. Network-only coding calls отделены от CPU-heavy jobs; проверенные bounded coding calls группируются под одну server allocation. На общем xorek одна heavy allocation и не более одного тяжёлого integration/model/live-fixture/OCI-build/restore task. Conflicting writes, shared heavy slots и release сериализуются. Production locks вслепую не удаляются.

7. Luna получает bounded задачи по low-risk UI, forms, docs, synthetic fixtures в независимых worktrees. Для отдельной Cloud-сессии сначала фактически проверяются выбор Luna, subscription, файловые инструменты, окружение; молчаливая подмена запрещена. Review-субагент не доказывает Cloud coding task. Auth, ACL, SQL, contracts, deploy остаются у назначенного backend/root owner.

8. Короткая progressive-disclosure карта `AGENTS`, versioned feature board, progress. Тёплая проверенная среда; feature-пакет даёт один наблюдаемый пользовательский результат. Документация и fixtures сдаются как конкретный артефакт. Малый progress/receipt хранит source SHA, artifact, checks, unresolved, next. Merge и release выполняет только root.

9. Dev checks local-first и пропорциональны — таблица в [TEST-MATRIX.md](TEST-MATRIX.md). Для неизменённого final exact SHA full required gate выполняется один раз перед release; новый candidate, failure или риск инвалидируют evidence → соответствующий gate повторяется. Сохраняются реальные ACL, idempotency, provenance, auth, restore matrix и обязательные release gates. Число тестов не становится целью. Duplicate test удаляется только после root-review с доказательством сохранившегося покрытия; тесты, зеркалящие реализацию, не добавляются. Fake pass и skipped-accepted недопустимы.

10. Свежие receipts перекрывают только датированный фактический статус (актуальные числа, SHA и receipts — в [TEST-MATRIX.md](TEST-MATRIX.md)). Политика остаётся в силе полностью: functional, ACL, citation, session, locks и mandatory gates продолжают действовать, включая ограничения, ранее записанные в README. Исторические замеры и неразвёрнутые кандидаты — указатели прошлого, не baseline.

11. Dev receipt кэшируется только для тех же tested files, dependency closure, schema и env; изменение source SHA инвалидирует release receipt. `stop_reason=max_tokens` и пустой JSON отклоняются. После failure идентичный retry запрещён: сначала максимум две исправленные self-fix попытки. Если не решено — сначала получить дополнительный контекст из первичных интернет-источников и подобрать применимые skills, затем предпринять ещё две исправленные попытки. Не повторять тот же вход без изменения гипотезы или данных. Если и это не помогло — сохранить полученный результат или точный blocker. Status-only model calls запрещены. `UNKNOWN` внешних writes сверяется в той же попытке.

12. Контекст: request/target 1M запрашивается только если provider и фактический интерфейс это поддерживают; никогда не заявлять недоступную capacity. Новая задача refresh-ит bounded контекст из текущей карточки/receipt/source, а не из всей истории. Compact на 70% фактически настроенного доступного контекста, если интерфейс даёт occupancy; при неизвестной телеметрии использовать bounded task packets и checkpoints вместо выдуманных значений.

13. Retention: логи, failed responses и промежуточные архивы с unresolved errors остаются до явного включения в исправления или контекст. После прохождения review модуля безошибочные воспроизводимые промежуточные артефакты могут быть удалены с проверкой exact target, зависимостей, retention и rollback. Сохраняются current production, required rollback, source, user data, originals, backups, active work, canonical acceptance receipts. Автоматическая массовая очистка и новые cleanup-задачи не создаются.

14. Решение владельца 15.10.2026: efficiency-first, parallel independent execution без простоя `executor → review → fix → re-review`. Завершение event-based — фиксируются фактические task, model, test, queue, acceptance и fix times; ускорение не заявляется без чисел.

## Research/Studio/maps runtime extension

Десять исходных MCP tools сохранены; четырнадцать аддитивных используют тот же authenticated catalog. Research/Studio работают с immutable selected-source snapshots, own-principal runs/notes, точными Unicode citation offsets и hashes, полной dependency RLS. Generated output остаётся draft. Runner держит существующий единственный slot на generation и conservative support verification. Runtime stream completion принимается только с configured model, thinking block, message_stop и end_turn; truncated/malformed output непригоден. No paid API fallback.

Studio: summary, FAQ, comparison, checklist, flashcards, persisted topic hierarchy, library-scoped semantic drafts. Sampling bounded и явно раскрывается; это не заявление о full-book coverage. Semantic relations typed и directed с evidence/hypothesis labels. Concept similarity overlay реализован и принят native 90/90. Ручная правка сгенерированных concepts сохраняет унаследованные source dependencies.

HTTP и MCP используют одинаковые функции. Публикацию semantic records выполняет только явный curator review; rule handoff создаёт draft и никогда usage/outcomes. Canonical graphs содержат только stored source/fragment/provenance/exact-version usage/outcome records. Audio/video/slides не реализованы. Новые функции не закрывают весь acceptance matrix по счёту тестов.
