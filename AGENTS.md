# AI-wisdom: правила разработки

Цель: закончить согласованный v1 по небольшим проверяемым функциям. Правила
этого репозитория не меняют модель сессии, полномочия или настройки других хостов.

## Начало задачи

- Проверить `pwd`, HEAD и `git status --short`; сохранить чужие изменения.
- Прочитать назначенную карточку, её receipt и только относящийся к ней код.
- [Правила исполнения](docs/workflow/FAST-DEVELOPMENT.md).
- [Выбор проверок](docs/workflow/TEST-MATRIX.md).
- [Волны и владельцы файлов](docs/workflow/PARALLEL-WAVES.md).
- [Шаблон задания](docs/workflow/task-template.json).
- [42 функции и границы готовности](docs/workflow/feature-board.json).
- Состояние сервера устанавливают свежие runtime receipts и MCP/readyz;
  исторические README и cloud capability snapshots не являются текущим статусом.

## Исполнение

- MiniMax по существующей OAuth-подписке — основной исполнитель ограниченных
  задач; Codex отвечает за архитектуру, независимую приёмку и интеграцию.
- Luna разрешена владельцем для ограниченных UI, документации и синтетических
  fixtures. Сначала проверить модель, инструменты, подписку и реальный workspace.
- Один результат, один владелец файлов, отдельный worktree. Параллельность
  разрешается после проверки зависимостей, ресурсов и фактической capacity.
- SQL, contracts, lockfiles, auth, общий `static/app.js`, runtime fixtures и
  release имеют одного назначенного владельца. Новые общие интерфейсы согласует root.
- Text chat возвращает артефакт; ему не приписывать доступ к файлам или тестам.
- Во время правок — focused checks. Перед выпуском — полный требуемый gate на
  точном кандидате. Не удалять проверки ради зелёного статуса.
- Исполнитель завершает в `review`; только root выставляет `accepted`.
- Не запускать повторно принятую задачу без изменения её входов или evidence.
- Запрос правил/плана не запускает разработку функций или production rollout.

## Неизменяемые границы

PostgreSQL — authority для прав и данных; индекс перестраиваемый. Один writer
OpenViking. Сохранить отрицательные ACL/RLS, provenance, версии, idempotency,
backup/restore и фактический MCP сценарий. Секреты и реальные книги не включать
в prompts или артефакты. Никакого PAYG coding fallback, изменения глобальных
AGENTS.md, миграции чужих проектов, GitHub push или release без текущего scope.
